## WP5 notes (2026-10-26, v0.5.0)
Implemented and tested offline (Linux, real child processes with the MockProvider): T-06 (no auto-approved tool, every call through `workers/permissions.py`; default mode never bypass), T-05 (task text quoted as inert JSON data; untrusted workspaces get git config overrides so repo-defined fsmonitor/hooks/diff/filter programs cannot run; tests build a hostile `.git/config` and a hostile hook), T-12 (mock runs get an environment without any credential; API runs get exactly one), T-22 (process-tree kill on cancel/hang/timeout/budget/shutdown, grandchild test; worktrees with changes or unmerged commits are never deleted), T-03 (worktree path re-validated with `resolve_within` + `git rev-parse` common-dir check each time it is used), T-04 (no shell anywhere: argument lists; a Bash tool call may only be one allowlisted command with no shell operator).
Findings made while building (all fixed before the PR, all with tests): (1) `git rev-list ... --exclude=refs/heads/<b>` does not match (patterns are relative to `refs/heads`), which made the "unmerged commits" check count 0 and would have let a worktree with committed work be deleted; (2) tools in the SDK's `allowed_tools` skip `can_use_tool`, so nothing is listed there; (3) a child started with the worktree as cwd would import modules from the untrusted repo: the child runs with `-I` and a neutral cwd; (4) a user pause/cancel through the task API while a worker lives would have left the process running: the API now stops the worker first; (5) `~` and drive-letter paths are refused by the file tools even though `resolve_within` would treat them as relative. From the automated review: (6) clearing `diff.external` does not stop per-driver `diff.<name>.command|textconv` (selected by `.gitattributes`); blanking them breaks git, so `git diff|show|log` are rewritten with `--no-ext-diff --no-textconv` and `git blame` is not allowed (test with a hostile driver); (7) the SDK session id is now published as soon as it is known, so a paused live run can be resumed; (8) the SDK's own `error_max_budget_usd` result is treated as a budget stop (`PAUSED_BUDGET`) and its cost reconciled.
NOT verified (needs the PC / Micah's go): Windows Job Object kill (`tests/workers/test_jobobject_windows.py`, marker `windows`), junction escape, the real Agent SDK run (no API call was made), LFS checkout behaviour.
New residual risks: T-34 in a TRUSTED workspace the repo's own hooks, test code and git config do run (by design; trust is Micah's decision per project). T-35 (line-length cap on the child's stdout) fixed in v0.5.1. T-36 after a hard crash of CPM on Linux (development only) children could outlive it; on Windows the Job Object kills them; WP9 reconciles runs left in RUNNING. T-37 the on-disk `spec.json` holds the task prompt (task title/description as typed), no secret. ## WP5 safety review (2026-10-26, v0.5.1, CPM Audit)
Reviewed `workers/{proctree,supervisor,permissions,worktree,events,providers}`, `api/runs`, `security/childenv`. Fixed, each with a test in `tests/workers/test_audit_wp5.py`:
1. **Cancel/pause racing a launch** (Medium): the task API only stops workers already registered live, so a cancel arriving between the task moving to RUNNING and the spawn left a running worker on a CANCELLED task. The supervisor now re-reads the task status before the spawn (no spawn) and right after registering the child (kill, run CANCELLED); `RunSupervisor.busy()` also covers the launch window and the worktree delete route uses it.
2. **Per-run cap multiplied by retries** (Medium, budget): the ceiling was checked per run only, so retries/resumes of one task could spend `ceiling x N`. All runs of a task now share one ceiling (`task_budget_microusd`, else `CPM_LIVE_RUN_MAX_MICROUSD`) minus the ledger sum for the task; a request above what is left is refused with the remaining amount (never clamped silently).
3. **Managed project path not re-validated at use** (Medium): the stored `projects.path` went straight to git. It is now resolved against the approved roots on every start (moved, junction or revoked path => refused, nothing changes).
4. **Protected-path check was case-sensitive** (High on Windows): `.Claude/settings.json` or `.GIT/hooks/x` passed the write filter on NTFS and would have planted hooks/MCP config. Matching is now case-folded, ignores trailing dots/spaces and refuses 8.3 short names (`CLAUDE~1`).
5. **`ls`/`python -m pytest|ruff|mypy` path arguments were checked textually only** (Medium): a symlink/junction committed in the repo could list or collect tests outside the worktree. They now go through `resolve_within` (T-03).
6. **Unbounded stdout line** (Low, closes T-35): one huge line was buffered whole. Lines over 1 MB are skipped to their end and logged as a warning.
7. **Stale kill on a recycled pid/process group** (Low): a pause timer firing after the worker ended could `killpg` a pid reused by someone else. `ProcessTree.kill()` is a no-op after `close()`. A failed `TerminateJobObject` is now logged instead of ignored.
8. **Program lookup in the current directory** (Medium on Windows): the child PATH could contain relative entries and `cmd.exe` looks in the cwd first. Relative PATH entries are dropped and `NoDefaultCurrentDirectoryInExePath=1` is set.
9. **WebSocket/REST replay re-parsed the whole log** (Low): replay now skips the first `since` lines without JSON parsing (one line per seq).
Accepted / open (not fixed here): T-39 on Windows the child is assigned to the Job Object right after `Popen`, not suspended, so a grandchild spawned in that microsecond window would escape (the worker is a Python interpreter still importing; use `CREATE_SUSPENDED` + `NtResumeProcess` if the Windows test shows otherwise; needs the PC). T-40 the heartbeat comes from a thread in the child, so a stuck SDK loop with a live heartbeat is only stopped by `max_runtime_s` (default 1 h, no model spend while stuck). T-41 in a trusted workspace a worker can write a test file and run pytest, i.e. execute code of its own making (same as T-34, by design of trust). T-42 no global budget admission yet (WP8) and no limit on concurrent WebSockets. Windows Job Object and junction behaviour remain NOT verified (`pytest -m windows` on the PC).

## WP15 notes (2026-10-26, v0.7.0)
Web UI added (`src/cpm/web`, plain HTML/CSS/JS, no build step, no third-party or remote code). Tested offline: `tests/security/test_ui.py`, `tests/integration/test_dashboard.py`, and a real-browser Playwright run (`tests/ui/e2e.mjs`: two projects in two tabs, live log, disconnect state; Linux/Chromium only).
Decisions: **T-27 resolved**: WebSockets authenticate with a one-time ticket (`POST /api/ws-ticket`, needs token + CSRF; random, 30 s, single use, bound to `/api/runs/{id}/stream`, max 64 outstanding; a wrong-path attempt burns it); the install token never goes into a URL and `?token=` is ignored. Origin is still mandatory. **T-39** the UI shell (`/`, `/ui/*`) is the only unauthenticated content besides `/health`; it holds no data and no token, is served under a strict CSP (`default-src 'none'; script-src 'self'; connect-src 'self'; frame-ancestors 'none'`, no inline script/style, no `unsafe-*`), and all dynamic text is inserted with `textContent` (a test bans `innerHTML`/`eval`/`document.write`/cookies/`sessionStorage` and any remote URL), so a hostile task title, file name or worker log line cannot run script. **T-40** the install token reaches the page through the URL fragment printed/opened by `scripts/start.ps1` (never sent to the server, removed from the address bar at once) and is kept in this origin's `localStorage` so a second tab works; a "Lock" button forgets it. Residual: the token is in the `start.ps1` browser command line for a moment and in the browser profile (same user/ACL exposure as `data/install_token`; accepted for a local single-user app). **T-41** a trusted/untrusted project is explained in the UI wherever tasks are shown (an untrusted project's workers do not load its CLAUDE.md).
Finding while building: uvicorn had no WebSocket library, so the WP5 live stream could not work outside the test client; `websockets` is now a locked dependency (hash lock regenerated, only that package added).
NOT verified: Edge/Firefox, the Windows browser, a real API-billed run from the UI (no live run was made).

## WP8 notes (2026-10-26, v0.8.0)
Checked: API key exposure (no endpoint reads or writes the key; budget routes handle money only), SQL (bound parameters, fixed table names), numeric abuse (amounts are `Decimal` with digit limits, positive, top-up at most 10,000 USD, prices at most 1,000 USD per million tokens, negative token counts refused), model id in the price route (regex, no path or traversal characters), a worker lying about cost (API runs are priced by CPM from the table, the child's `cost_microusd` is ignored; mock-only exception), money endpoints behind token + Host/Origin + CSRF like every route (tested 401 without token), concurrency (threaded admission test; mutation check: without `BEGIN IMMEDIATE` the test fails in 5 of 5 seeds), events carry amounts only.
Findings made while building (fixed with tests): (1) the app builds the supervisor before migrations run, so the price table loads lazily; (2) an audit event stored a Python repr instead of JSON and broke `GET /api/tasks/{id}` (the test caught it); (3) a hold plus the same run's spend would have been counted twice (exposure uses `max(0, hold - run spend)`).
Accepted / open: T-40 a single message can overshoot a run's hold by its own cost (soft limit by design; the kill happens after the usage event, as in WP5); T-41 holds of a crashed CPM stay until WP9 calls `release_orphans`; T-42 estimates can under-count if Anthropic changes prices or the price table is stale (re-check `prices` at every release, `verified_on` is shown); T-43 month boundaries use UTC; a run that spans midnight is counted in the month of each message; T-44 the manual credit balance and Console figure are typed by the user and trusted.
